== why the per-target asymmetry (shipped adapter source, same file) ==
- runCore (lines ~402-433) spawns the child with stderr:"ignore", returns {stdout, code}.
- validate-state (line ~1674) + session-end (~954): advisory `runCore(...); return 0` — failure fully silent.
- session-start (~916-946): runCore; marker write gated on r.code===0 → no marker; empty stdout re-wraps to nothing; return 0. Silent.
- continue-workflow (~1681-1687): `return r.code` — forwards the child's exit 2, stderr ignored → silent exit 2 on Stop.
- The four PreToolUse guards + deliver-stage-rules go through runCoreWithStderr (stderr piped): adapter exits 2 and the child's "unknown command 'hook'" lands on stderr → every guarded tool call is hard-blocked with a misleading dispatcher error.
