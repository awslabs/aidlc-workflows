# Design Agent

> **エージェント詳細解説** · [ユーザーガイド](../00-introduction.md) › [エージェント](../06-agents.md) › [詳細解説](README.md) · 技術リファレンス: [design-agent](../../reference/agents/design-agent.md)

aidlc-design-agent は、あなたの UX/UI デザイナーです。Ideation ではワイヤーフレームとコンセプトのスケッチを作成し、Inception ではそれらをインタラクション仕様を伴う高忠実度のモックアップへと発展させます。情報アーキテクチャ、ナビゲーション設計、レスポンシブな挙動、アクセシビリティ要件を定義します。UI を持たないプロジェクトでは、システムコンテキスト図と API のエクスペリエンス設計を作成します。

aidlc-design-agent は、2つのステージを主導し、ほかの2つを支援します。ユーザーに触れるすべてのインターフェースが、使いやすく、アクセシブルで、デザインシステムの標準に沿うよう取り計らいます。

## 主導するステージ

| ステージ | フェーズ | 説明 |
|-------|-------|--------|
| 1.6 Rough Mockups | Ideation | 低忠実度のワイヤーフレームとコンセプトの可視化 |
| 2.5 Refined Mockups | Inception | インタラクション仕様とアクセシビリティを伴う高忠実度のモックアップ |

## 支援するステージ

| ステージ | フェーズ | 貢献 |
|-------|-------|--------|
| 2.4 User Stories | Inception | コラボレーターがオンのとき、インタラクションの詳細と UX の受け入れ基準でストーリーを充実させる |
| 2.6 Domain Design | Inception | UI コンポーネントの仕様を提供する |

## 期待できること

aidlc-design-agent が稼働しているとき、画面レイアウト、ユーザーフロー、インタラクションパターンの詳細な記述を markdown で生み出します。対象デバイス、アクセシビリティ要件、デザインシステムの好みについて問いかけます。インタラクションは、具体的な画面の状態と遷移、すなわち loading、success、error、empty、partial の各状態として記述します。

## 協働のしかた

aidlc-design-agent は、aidlc-product-agent から intent とユーザーストーリーを、aidlc-architect-agent からコンポーネントの制約を受け取ります。そのモックアップとインタラクション仕様は、実装のために aidlc-developer-agent へ、UX の受け入れテストのために aidlc-quality-agent へ引き継がれます。

## 主要な原則

- 一目で把握できるよう設計する。重要なアクションはすぐ目に入らなければならない
- 一貫性が認知負荷を下げる。すべてのインタラクションパターンは予測可能であるべきである
- エラーメッセージよりエラーの予防を。エラーを起こしにくくする
- WCAG のアクセシビリティ準拠は、努力目標ではなく最低ラインである
- 最悪のケースを想定して設計する。empty 状態、error 状態、遅い接続を想定する
