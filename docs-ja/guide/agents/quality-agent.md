# Quality エージェント

> **エージェント詳説** · [ユーザーガイド](../00-introduction.md) › [エージェント](../06-agents.md) › [詳説](README.md) · 技術リファレンス: [quality-agent](../../reference/agents/quality-agent.md)

aidlc-quality-agent は、あなたの QA エンジニアであり性能の専門家です。テスト戦略を定め、テストスイート（ユニット、統合、契約、セキュリティ）を生成し、受け入れ基準に対するカバレッジを検証し、負荷テストを設計・実行し、非機能要件の目標を検証します。実装された各 Unit が受け入れ基準を満たし、システム全体が品質ゲートを満たすようにします。

aidlc-quality-agent は、Construction と Operation で 1 つずつ、計 2 つのステージをリードし、ほかに 3 つのステージを支援します。ビルドツール、テストコマンド、性能テストのユーティリティを実行するための Bash アクセスを持ちます。

## リードするステージ

| ステージ | フェーズ | 説明 |
|-------|-------|-------------|
| 3.6 Build and Test | Construction | ビルドを実行し、テストスイートを生成・実行し、品質ゲートを検証する |
| 4.6 Performance Validation | Operation | 負荷テスト、NFR 検証マトリクス、キャパシティ計画 |

## 支援するステージ

| ステージ | フェーズ | 貢献 |
|-------|-------|-------------|
| 2.2 Practices Discovery | Inception | 協力者がオンのとき、互いに見えないテスト姿勢のスポーク。自分の貢献ファイルを書く |
| 2.4 User Stories | Inception | 協力者がオンのとき、モブの中でテスト可能性と受け入れ基準の声を担う。自分の貢献ファイルを書く |
| 3.2 NFR Requirements | Construction | テスト可能な品質属性のシナリオを定める |

## 何が起きるか

aidlc-quality-agent が動いているときは、ビルド手順とテストスイートを生成し、実装されたコードに対して実行します。Build and Test の間は、プロジェクトのビルドシステムを走らせ、ユニットテスト、統合テスト、そのプロジェクトに適したほかの種類のテストを実行します。合否の結果、カバレッジの指標、品質ゲートの状態を報告します。

Operation フェーズの Performance Validation の間は、負荷テストを設計・実行し、NFR の目標（レイテンシのパーセンタイル、スループット、可用性）を検証し、目標と実績を比べる NFR 検証マトリクスを生み出します。

## どう協働するか

aidlc-quality-agent は、受け入れ基準つきのユーザーストーリーを aidlc-product-agent から、NFR の目標を aidlc-architect-agent から、実装されたコードを aidlc-developer-agent から受け取ります。セキュリティテストの要件について aidlc-devsecops-agent と、CI 統合について aidlc-pipeline-deploy-agent と協働します。そのテスト結果と性能のベースラインは、aidlc-operations-agent に引き継がれます。

## 中心となる原則

- 実装ではなく、要件をテストする
- テストピラミッドに従う。速いユニットテストを多く、統合テストを少なく、エンドツーエンドを最小に
- 欠陥が見つかったら、直す前に、それを再現するテストを書く
- テストは、実行順序や共有状態に依存してはならない
- カバレッジは目安であって目標ではない。意味のない表明による 100% より、考え抜いたテストによる 70% が勝る
