# Operations Agent

> **エージェント詳細解説** · [ユーザーガイド](../00-introduction.md) › [エージェント](../06-agents.md) › [詳細解説](README.md) · 技術リファレンス: [operations-agent](../../reference/agents/operations-agent.md)

aidlc-operations-agent は、あなたのサイトリライアビリティエンジニアであり、インシデントマネージャーです。デプロイされたシステムが、観測可能で、レジリエントで、継続的に改善されるよう取り計らいます。CloudWatch のダッシュボードとアラームから、X-Ray トレーシング、SLO 追跡、インシデント対応 runbook、カオスエンジニアリングの検証まで、運用レイヤーを所有します。とりわけ、本番環境からの知見を次のイテレーションに向けて Ideation へ還流させ、フィードバックループを閉じます。

aidlc-operations-agent は、Operation フェーズの3つのステージを主導します。監視のセットアップコマンド、runbook スクリプト、診断ツールの実行のために Bash を利用できます。

## 主導するステージ

| ステージ | フェーズ | 説明 |
|-------|-------|--------|
| 4.4 Observability Setup | Operation | ダッシュボード、アラーム、トレーシング、構造化ログ、カスタムメトリクス |
| 4.5 Incident Response | Operation | SSM runbook、インシデント計画、エスカレーションマトリクス、オンコール体制 |
| 4.7 Feedback & Optimization | Operation | SLO レポート、コスト分析、ドリフト検知、フィードバックループ |

4.6 Performance Validation は aidlc-quality-agent が主導します。このエージェントが 4.4 でセットアップする運用テレメトリとベースラインは、その作業を非公式に支えますが、4.6 の正式な支援エージェントではありません。

## 支援するステージ

なし。aidlc-operations-agent は主導専門のエージェントであり、ほかのエージェントのステージを支援しません。その主導するステージはすべて Operation にあり、そこでライフサイクルのループを閉じます。

## 期待できること

aidlc-operations-agent が稼働しているとき、監視の好み、SLO の目標値、インシデント対応のプロセス、オンコール体制について問いかけます。CloudWatch ダッシュボードの構成、しきい値と通知先を伴うアラーム定義、X-Ray トレーシングのセットアップ、よくあるシナリオ（サービス再起動、キャッシュのフラッシュ、フェイルオーバー）向けの SSM runbook、そしてエスカレーション経路を伴うインシデント重大度の定義を生み出します。

Feedback & Optimization（最終ステージ）の間には、本番環境のメトリクスを分析し、最適化の機会を特定し、運用上の知見を次の開発サイクルに向けて aidlc-product-agent へ還流させるフィードバックループのドキュメントを作成します。

## 協働のしかた

aidlc-operations-agent は、aidlc-aws-platform-agent からプロビジョニングされたインフラを、aidlc-pipeline-deploy-agent からデプロイされたサービスを受け取ります。性能のベースラインと SLO の検証では aidlc-quality-agent と、アプリケーションレベルのログ改善では aidlc-developer-agent と連携します。そのフィードバックレポートは、Operation から Ideation へ戻る橋渡しとなり、ライフサイクルのループを完結させます。

## 主要な原則

- 網羅的なテレメトリを収集する。ただしアラートはユーザーに影響する問題だけに絞る。アラート疲れは対応を鈍らせる
- SLO が信頼性の目標を定める。ほかのすべてはそこから導かれる
- すべてのインシデントは学びの機会である。犯人探しをしないポストモーテムが、インシデントを改善へと変える
- テストされていないレジリエンスの仕組みは仮定にすぎない。カオスエンジニアリングがそれを検証する
- Ideation へ還流しない本番環境の知見は、無駄になった学びである
- 手作業の運用労苦はなくさなければならない。繰り返せる runbook のステップはすべて自動化する
