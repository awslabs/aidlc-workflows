# Kiro Windows 出力エンコーディングの証拠

このディレクトリは、`2.6.75` の Kiro コマンド出力の修正に関する、編集済みのネイティブ Windows の証拠を保持しています。完全な診断キャプチャには、一時的なワークスペースのパス、セッション識別子、IDE の DOM スナップショット全体が含まれます。チェックインされた NDJSON は、正確なコマンド出力とモデルのフォローアップテキストを残しつつ、それらのマシンローカルなフィールドを安定したメタデータに置き換えています。

## キャプチャが証明すること

`kiro-ide-windows.ndjson` は、3 つのサーフェスを分けます。

1. 現在のベースラインの決定論的なツール出力。
2. その出力の後に付加されるシェルトランスポートのサフィックス。
3. モデルの別個のフォローアップの散文。

Kiro IDE 1.0.242 では、復元された所見の Unicode の文字化けが再現しなくなりました。この変更の前から `█`、`▒`、`░`、`─`、`✓`、`⇄`、`—` は無傷でした。ESC バイトで終わるシェルの断片は、status と doctor の両方の後で依然として再現しました。この区別は重要です。ホストのバージョンの挙動が変わった一方で、残るトランスポートの欠陥とモデルの言い換えは独立していました。

修正後のキャプチャは、`aidlc-terminal-command` と `aidlc-terminal-command-guard` を使います。正確な Unicode 出力を残し、PowerShell/ESC のサフィックスを記録せず、Allow のクリックをゼロで済ませ、モデルのサマリーがあれば別個の `model_followup` フィールドに残します。

`kiro-cli-windows.ndjson` は、現在のベースラインと修正後のペアを保持します。各行には、ネイティブアダプターの `transport` が、実際の ACP の `model` サーフェスとは別個に含まれます。現在のベースラインでは、CLI のトランスポートはすでに UTF-8 を保ち、ゴミを運びませんでした。モデルは、決定論的なブロックの後にフォローアップの散文を加えました。修正後の行は、同じトランスポート／拒否のセマンティクスを保ちます。4 つの ACP ターンはすべて `stop_reason: "end_turn"`、ツール呼び出しゼロ、ツール呼び出しの問題ゼロで終わります。
