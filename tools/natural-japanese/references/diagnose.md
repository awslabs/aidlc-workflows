# 診断モード(score):書き換えずに、AI臭さをスコアと理由で返す

診断モードは文書を一切書き換えず、スコア、その根拠、直すなら何からか、の3点だけを返す。「この文章、AIっぽい?」「どれくらいAI臭いか採点して」という依頼に答えるためのモードで、リライトを求められたら通常の工程(SKILL.md §1〜7)へ切り替える。

## 3段階の深さ

診断の quick / full / exp は、どこまで深く見るかの指定である。書き換えの工程がないので、SKILL.md の実行モードとは中身が違う。食い違うときは、この節に従う。

- quick(既定):`lint.py --json`(ジャンルが分かれば `--genre`)を1回と、見出しと各段落の先頭文にざっと目を通す。サブエージェントは使わない。30秒程度
- full:quick に加えて `outline.py` と `terms.py` を実行し、構造の点検・読みやすさの点検・文書タイプの照合(SKILL.md §5)の結果を判断に入れる。長い文書を分担して読むと速い場合だけサブエージェントを使ってよい。診断では収束の確認は行わず、1回の評価で終える。数分
- exp:full に加えて 実験的な検出器の `semantic.py --json` を実行する。初回に約1GBのモデルをダウンロードするので、初回は始める前にユーザーに伝える。言い回しを整えたあとにも残る、話題の平板さまで見る

## スコアの算出:機械ベースと判断調整の二層

スコアは0〜100の自然度で、高いほど自然(AI臭が薄い)。ユーザーへ返すときも向きを一言添える。二層で作り、内訳を必ず開示する。

機械ベース(決定的):100点から lint の指摘を文書長で正規化して減点する。critical・warn・info は、lint のテキスト出力では「重大」「警告」「情報」と表示される。

```
減点 = (critical×8 + warn×4 + info×0.5) × (1000 / max(文書の文字数, 1000))
機械ベース = max(100 − 減点, 20)
```

文書の文字数は本文全体の文字数。改行・Markdown記法込みの len でよい(目安の正規化なので厳密さは要らない)。短い文書ほど1件の重みが大きく、長い文書では件数よりも密度で減点される。係数は、critical の指摘1件が warn 2件、info 16件に当たるように置いた目安である。下限の20は、機械の指摘だけでスコアが0近くまで下がらないようにするための値。exp で semantic_topic_flatness(warn)が出た場合も同じ式に含める。本文が空か実質空(100字未満)の場合はスコアを出さず「診断対象として短すぎる」と返す。

判断調整(±15点の範囲):full / exp では、構造と読みやすさの点検で見つけた問題で調整する。lint では検出できない、次のような構成の癖は減点する。

- どの節も同じ組み立てになっている
- 根拠や関係のない箇条書きを並べている
- 確信の度合いが書き分けられていない
- レポートで、次にすべきことが書かれていない
- もともと並列な項目に順位を付けている

lint が誤検知気味でも、文脈上自然と判断した指摘は減点を戻す。quick では調整せず機械ベースをそのまま使う(そのぶん「quick の精度は粗い」と明記して返す)。調整後の最終スコアは 0〜100 に切り詰める(min(max(スコア, 0), 100)。機械ベースが100で加点調整しても100を超えない)。

スコアは判断を含む目安であり、同じ文書でも数点は揺れる。CI のゲートに使う数値ではない。この注意は結果に一言添える。

## バンドと言い方

| スコア | バンド | 伝え方の例 |
|---|---|---|
| 90〜100 | 自然 | AI臭はほぼ見当たらない。指摘があっても好みの範囲 |
| 70〜89 | 軽微 | 数カ所に癖が残るが、読み手が「AIっぽい」と感じる可能性は低い |
| 50〜69 | 要修正 | 表層か構造のどちらかに明確なAI臭がある。直す価値がある |
| 0〜49 | 濃厚 | 複数のカテゴリで強く検出。リライト推奨 |

## 出力の形式

1. スコアとバンド(機械ベースと判断調整の内訳つき)
2. 主な理由を3〜5個:カテゴリ名でなく中身で書く。「『〜ではなく』の対比が全文の文のうち4%で機械的なリズムになっている(L12ほか)」のように、代表箇所の行番号と、なぜそれがAI臭なのかを一言で
3. 直すなら何から:効果の大きい順に2〜3個。ただし診断モードでは直さない。「リライトしますか(quick/full)」と添えて終える

理由は lint の detail の転記ではなく、文書の文脈に即して言い直す。指摘が多い場合も全部は並べず、スコアをもっとも動かしたものに絞る。
