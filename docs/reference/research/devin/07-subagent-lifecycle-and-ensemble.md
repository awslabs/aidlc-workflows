# Ensemble dispatch, reviewer attribution, and subagent lifecycle

**Finding:** DEVIN-07. **Status:** Protocol binding implemented; native dispatch translation implemented, regression-covered, and accepted live on Devin CLI 3000.10.31 (2026-09-18, full workflow completed); background lifecycle implemented, regression-covered on 3000.10.31 captures, and accepted live on 3000.10.31 (2026-09-19, background-lifecycle acceptance); reviewer attribution implemented as a foreground reviewer window, regression-covered on the 3000.10.31 Item 4 captures, and accepted live on 3000.10.31 (2026-09-20, reviewer-scope acceptance, R1–R6 PASS, R7 partial) with four follow-up findings F1–F4 open (two core-scanner false positives, one silent adapter fail-open, one architecture proposal). **Source baseline:** `c29db7cc` plus uncommitted Item 4 change. **Fact-checked:** 2026-09-20.

## Why this was needed

Adding Devin to the packaging roster did not tell the conductor how to execute subagent, pipeline, or mob topologies. Correct specialist dispatch also requires task translation, rule delivery, trustworthy reviewer attribution, and completion evidence—not just a native tool call.

## Current implementation

The shared ensemble protocol now has a Devin binding and the Devin orchestrator requires dispatched topologies to dispatch rather than silently run inline. The parent selects a named profile, coordinates participants, reads returned work, and owns questions. Foreground dependencies are sequential; parallel supports use background dispatch. Contribution files and pipeline-link receipts remain engine evidence, separate from SUBAGENT_COMPLETED telemetry.

The observed native dispatch fields are profile, task, is_background, and title. The adapter now normalizes `run_subagent` input through `normalizeRunSubagentInput` — `profile` to `subagent_type`, `task` to `prompt`, `is_background` to `run_in_background` — for both PreToolUse arms. The Plan Approval arm forwards the real `task` brief, so an approved developer dispatch is judged on the conductor's actual markers; legacy `agent`/`prompt` reads were dropped (no capture or live run ever produced them). Before the fix, the 2026-09-17 attended run reproduced the mismatch live on 3000.10.31: the conductor placed `AIDLC-STAGE: code-generation` and `AIDLC-TESTING-CONTRACT: …` at the top of `task`, the adapter forwarded an empty `prompt`, and the guard refused every developer dispatch with `(missing marker)` despite a valid receipt (session-isolation acceptance, 2026-09-17; raw artifacts at `evidence/devin-e2e-run/session-isolation-run/`). The guard's zero-marker refusal text now names the actual defect ("carries no target marker") instead of claiming the plan is unapproved, so a conductor is no longer misdirected into re-presenting Plan Approval.

Stage-rule delivery now normalizes the native input before piping to the shared hook, so `profile` resolves as the agent identity (the core still scans `subagent_type`/`agent_type`/`agent`/`role`; the adapter owns the alias). The core's `updatedInput` rewrite is translated back to a Devin-native `{task}`-only subset — Devin merges `updatedInput` into the tool arguments — so the active-stage bundle lands inside the brief field Devin actually sends, and the injected aliases never reach the host. Devin applying a `task` rewrite to `run_subagent` was observed live on 3000.10.31 (2026-09-18, native-dispatch acceptance; raw artifacts at `evidence/devin-e2e-run/native-dispatch-run/`): the child received the brief plus one bundle while the parent-side record kept the pre-merge arguments.

Reviewer attribution is a Devin-only **foreground reviewer window**. Devin child events carry no identity on any captured build (C04/C09 on 3000.6.14; C17 on 3000.10.31 re-proved the six-key envelope with no `profile`/`agent_type`/`agent_id`), Devin offers no per-profile hook registration (frontmatter fields are exactly `name`/`description`/`model`/`allowed-tools`/`max-nesting`), and no `DEVIN_*` environment variable names a subagent. The only host-carried identity is the parent's `run_subagent` `tool_input.profile`, and the host guarantees the parent pauses during a foreground child while nesting is off — so the adapter's `reviewer-scope` arm opens `<record>/.aidlc-engine/reviewer-window/<session_id>.json` `{version, sessionId, toolUseId, profile, promptId?, openedAtMs}` when a foreground dispatch names a `REVIEW_AGENT_RE` profile AND a fresh `reviewer-dispatch.json` names that same reviewer (task text is never read). While the window is open, every `read`/`notebook_read`/`glob`/`grep`/`edit`/`write`/`notebook_edit`/`apply_patch`/`exec` PreToolUse on that session is normalized to the Claude shape (`glob_pattern → glob`, content `pattern` dropped, `exec.workdir → cwd`) and piped to the shared `aidlc-reviewer-scope.ts` with `agent_type: <profile>`; the core's identity check and matcher decide, exactly as on Claude Code. The window closes at the dispatch's PostToolUse (`log-subagent` arm), `UserPromptSubmit`/`ask_user_question` (human boundaries), `SessionStart`/`SessionEnd`, a `run_subagent`/`read_subagent` PreToolUse (tools a child cannot hold), the adapter's own denial of the dispatch (C21: a hook-denied `run_subagent` emits no PostToolUse), and the 6h dispatch TTL. `Stop` is deliberately NOT a close point: the child's own Stop enters the shared stream before the parent's PostToolUse and `continue-workflow` may block it, after which the child continues. Two dispatch-time refusals keep the window exact (C19 showed a background child's events interleave inside a foreground reviewer's window under one `session_id`): a reviewer dispatched with `is_background: true`, or while `aidlc/.aidlc-subagent-inflight` holds a fresh entry for the session, is refused with exit 2 and a remedy. While attributed, a reviewer call naming `reviewer-window` is refused (attribution state is read-only for the reviewer). Everything else fails open with a drop line; `AIDLC_DISABLE_REVIEWER_SCOPE_HOOK=1` disables the arm's own refusals as well. The two review-only profiles ship `allowed-tools: [read, write, edit, grep, glob, exec]` (only the tools a review uses; `write_to_process` was the one unscanned shell channel).

The background lifecycle is now reconstructed the way Claude Code sees it. Devin dispatches no `SubagentStop` event (C16 on 3000.10.31: the key is not loadable in either hooks.v1.json — where it poisons the whole file and the CLI loads zero hooks — or .claude/settings.json), so the adapter synthesizes the pair Devin does emit: a `run_subagent` launch-ack PostToolUse annotates the core in-flight entry (created at the dispatch PreToolUse via the `is_background → run_in_background` translation) with the embedded `agent_id` and `profile` — no audit row; a terminal event (a foreground or resumed `run_subagent` completion, or a `read_subagent` terminal read) forwards a synthesized `SubagentStop` payload — `session_id`, `agent_id`, `agent_type` (the dispatch profile, or the ledger entry's type for reads), `last_assistant_message` — to the shared hook, which removes exactly that entry and appends one `SUBAGENT_COMPLETED` naming the profile and agent id. The PostToolUse `log-subagent` matcher now covers `run_subagent|read_subagent`; repeated reads and foreign ids are no-ops, and the core's exact-id completion rule keeps a foreground completion from consuming a background entry. On the 3000.10.31 captures a `Stop` hook DOES fire while a background child is still in-flight — the pending-subagent carve-out is load-bearing — and the CLI keeps the turn active until the child finishes, delivering the completion notification and a second `Stop` under the same `prompt_id`.

### Native dispatch translation contract (upgrade checklist)

When Devin changes its `run_subagent` argument shape, or the core dispatch hooks change the fields they read or rewrite, the contract to keep is: the adapter is the only place that knows Devin's field names. Inbound, `profile` is the sole identity and `task` the sole brief (`profile`→`subagent_type`, `task`→`prompt`, `is_background`→`run_in_background`; legacy `agent`/`prompt` are not read). Outbound, a stage-rule rewrite is emitted as the smallest Devin-native subset, `updatedInput: { task }` only — never `prompt`, `subagent_type`, or `run_in_background` — relying on Devin's documented subset merge; a host that replaced arguments wholesale would drop `profile` and fail visibly, which is preferable to running the wrong profile silently. The rewrite source is whichever core field differs from the original task: the core's `withPrompt` writes into `prompt` first, so a translation that reads only `updated.task` silently discards the bundle. The shared guard's zero-marker refusal must name the malformed handoff and tell the conductor not to re-present a recorded Plan Approval; the audit `Unit: (missing marker)` value stays.

The deterministic cases to keep green live in t332 under `Item 2`: approved stage-level dispatch with markers in native `task` allows and adds no `PLAN_APPROVAL_BLOCKED` row; the same brief without approval blocks with the one-target wording and audit `Unit: stage:code-generation`; a developer `task` with no marker blocks with "carries no target marker" and never "not currently approved"; non-developer and legacy-field payloads are allowed early; rule delivery for an AI-DLC profile emits a `{task}`-only `updatedInput` with exactly one bundle (also with `is_background: true`); built-in and `EXEMPT_AGENTS` profiles and an already-bundled `task` produce empty stdout; a core exit 2 is forwarded; malformed stdin is fail-open. t265 pins the zero-marker and several-target wording. The t332 seeding helper must stamp `state_sha256` with `stateDigest(state)` (as t149 does), otherwise the seeded directive is stale and the guard refuses before ever evaluating the dispatch.

### Background lifecycle contract (upgrade checklist)

When Devin changes its subagent output envelopes or event surface, the contract to keep is: the adapter is the only place that reads Devin's `tool_response.output` strings, and the core ledger is the only correlation store — same file, session scoping, TTL, and lock as Claude Code, plus optional `agentId`/`agentType` on entries. A launch ack must never reach the core (it annotates; SubagentStart parity is "no audit row"); a terminal event forwards exactly one synthesized `SubagentStop` (`session_id`, `agent_id`, `agent_type`, `last_assistant_message`), correlated by exact `agent_id` — rule 2 of `completeSubagentInflight` makes a session with annotated entries immune to id-less consumption. `read_subagent` forwards only while its id is pending; a FOREGROUND `run_subagent` stays fail-open on unrecognized output so a real completion is never dropped, while a BACKGROUND `run_subagent` with unclassifiable output (neither launch ack nor terminal envelope) drops with a `log-subagent` drop line — a background dispatch's PostToolUse is not a terminal event, so it must never mint an id-less completion. `SubagentStop` must never be registered in Devin hook config — an unknown event key poisons the whole `hooks.v1.json` (CLI logs `unknown variant` and loads zero hooks).

The deterministic cases to keep green live in t332 under `Item 3` (cases 1-13 plus rewritten test 11) and in t327's ledger rules (annotate-newest, exact-id, legacy splice, malformed, TTL, session isolation). The classifier strings are pinned from `native-contracts-3000.10.31.json` and the 3000.10.31 binary; the `exited with an error` read form is binary-pinned only — a denied-tool child reads as `completed` and its failure survives only in the child's own Stop message, which arrives in the parent's hook stream with the same `session_id`/`prompt_id` and no attribution.

Residual limitations: a background agent whose result the parent never reads, or that is cancelled from the panel, has no hook-observable terminal event and ages out under the 2h TTL (during which the Stop carve-out relaxes forwarding-loop enforcement for that session); an entry is id-less between its dispatch PreToolUse and the launch-ack, so a same-session foreground completion in that window still consumes it (parallel tool batch edge); the output-string contract is undocumented and must be re-pinned per Devin version; child tool calls still carry no identity, so reviewer attribution stays open.

### Reviewer window contract (upgrade checklist)

When Devin changes its dispatch fields, foreground semantics, or event surface, the contract to keep is: identity comes from the host's `run_subagent` `profile` field only (never task text, never `tool_use_id` formats); attribution is exact only under one-foreground-child-at-a-time (parent paused, nesting off, no pending background entries), so any host change that lets parent or background events land inside a foreground window must turn into a dispatch-time refusal, never a guess; the core hook stays the sole decision-maker (`agent_type` + dispatch record + matcher); the window is closed by every boundary the host guarantees and by the adapter's own denials, but never by `Stop`; every unknown fails open with a drop line. If a future build adds a structured child identity field, prefer it over the window and retire this section with a supersession note.

The deterministic cases to keep green live in t332 under `Item 4` (1–24), t331 test 19, and t333's Devin foreground-reviewer pin. The Phase 0 captures that justify the design are C17 (window bounds, no identity, shapes), C18 (exit 2 denies a child), C19 (interleaving), C21 (denied dispatch has no PostToolUse) — recorded in `native-contracts-3000.10.31.provenance.json`; the broad Item 4 capture file was removed under Item 9.

### Reviewer-window decisions retained from PR #996 Item 4

The owner decisions behind the window design, recorded when the standalone Item 4 plan was folded into this finding:

1. Attribution uses a foreground reviewer window sourced only from the parent `run_subagent.tool_input.profile` plus a fresh matching reviewer-dispatch record; task text and `tool_use_id` formats never establish identity.
2. A reviewer dispatch with `is_background: true` is refused, and a reviewer dispatch while a background entry is pending is refused; ambiguity is decided at dispatch, never guessed per child call.
3. Window storage is `<record>/.aidlc-engine/reviewer-window/<session_id>.json` — intent-scoped, gitignored, TTL-janitored; the subagent in-flight ledger is not reused.
4. The reviewer profiles retain exactly `[read, write, edit, grep, glob, exec]`; `exec` supports review-brief tooling and the observed heredoc write fallback, while unused notebook/todo/web/process/MCP/apply_patch tools remain excluded.
5. Post-intervention residuals (Ctrl+B, panel cancel, host-denied dispatch) fail open with a drop line and an explicit limitation rather than imposing a stale global reviewer restriction.
6. The Phase 0 host capture was the go/no-go: C17 shapes, C18 child-call exit-2 denial, C19 interleaving, C21 denied-dispatch behavior; interactive C15'/C20/C22 remained BLOCKED unless attended. Synthetic adapter tests alone were insufficient.

**Follow-ups from the live run (open):**

- **F1 (core `aidlc-reviewer-scope.ts`, false positive):** `judgeCommandText` tokenizes heredoc bodies as operands, so a review written via `cat > … <<'EOF'` whose prose contains the bare word `construction` (or a sibling path it is asked to name as an integration point) is blocked with `Target: construction`; observed three times before the reviewer removed the word. Devin-exposed because the child has no `write`. Fix: treat heredoc bodies as data unless the consuming command is a shell/interpreter.
- **F2 (adapter):** a present-but-invalid dispatch record (parse failure) opens no window and refuses nothing; the core logs `reviewer dispatch record is malformed; enforcement skipped` per forwarded call (22 lines over two episodes) but nothing reaches the conductor, and the adapter comment's assumption that "the core's missing-record advisory covers attributed calls" cannot hold without a window. Fix: record present but invalid/stale/mismatched at the reviewer dispatch → exit 2 with the documented shape as remedy; record absent → drop line only (single-stage reviews write none).
- **F3 (architecture, owner decision):** the conductor wrote three well-formed records, then after compaction wrote the `aidlc-log review` request JSON (`stage/unit/iteration/reviewer/requestId/reviewFile`, no `exempt`) twice — including once after an explicit shape instruction — and both episodes let the reviewer `ls`/`cat`/`glob`/`read` the sibling unit unrefused. Proposal: `aidlc-log review` writes the record when `--unit` is given and deletes it on `--verdict`, taking the model out of the policy-state path (cross-harness).
- **F4 (core, false positive):** `cd <project-root> && …` is judged as a search-root sweep because the root contains `construction/`; blocked with `Target: <project-dir>`. `cd` should only rebase later relative paths. Side effect observed: the reviewer misreported this refusal as the cross-unit refusal and skipped the sibling read.

Superseded: a Kiro-style per-agent hook registration for Devin (the host has none); profile selection alone makes both core dispatch hooks fully compatible; a background launch can stand in for completion; ignoring read_subagent is completion deduplication; absent child identity can be guessed from tool_use_id prefixes; a hook registration proves reviewer read enforcement. The older instruction that status reconciles stuck background bookkeeping has no established repair contract here.
