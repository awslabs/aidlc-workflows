## Design and scope

1. Make repair lazy: only a strict JSON syntax failure invokes the existing transformer. If it makes no change, return null; otherwise parse the repaired text. Apply the existing version, digest-shape, and body-hash validation unchanged. Never retry syntax-valid but invalid/tampered contracts.
2. Extend `parseTestingContract(plan, source?)` with optional `{ projectDir: string; planPath: string }`. Existing text-only callers remain pure. Pass source identity at all production callsites. Only after repaired JSON passes all existing validation, append a `testing-contract-repair.drops` record with a JSON-escaped project-relative filename. Do not log plan text, contract values, or claim the current harness caused the corruption. Each successful file-backed repair read is one event; repeats are historical reads, not unique corruption incidents. No automatic source-file rewrite.
3. Suppress persistent telemetry in read-only Stop/route probes. These keep the same parse result and do not create health directories. Ordinary file-backed reads provide persistent evidence. The existing best-effort log semantics mean disk/permission failures cannot change parser acceptance.
4. Extend the existing doctor drop scan with a specific `Testing-posture contract was read via repair (historical)` warning. Include the affected filenames, read count, retained log path, and remediation. Deduplicate displayed reasons only, not recorded events. Preserve all unrelated degraded/advisory checks and exit behavior. Do not scan or repair source plans from doctor itself. Retained history is not proof that a file is still corrupt or that a host bug persists.
5. Keep the narrow repair shared: existing artifacts may be opened by another harness, and parsing text cannot reliably attribute corruption to its writer. This follow-up makes existing compatibility visible; it does not add a harness/version bypass or relax validation.
6. Add a removal TODO next to the workaround: fixed Devin CLI version UNCONFIRMED as of 2026-09-12. Record the first vendor-confirmed fixed version and a captured write/read escape regression; once the supported baseline includes that version and affected stored plans have been regenerated through normal approval, remove the fallback. Retained drop absence alone is not proof that the workaround is unused. Record the same condition in PR #996's description.
7. Update troubleshooting guidance and synchronized version/changelog/README to 2.9.7. Generated `dist/` and `dist-release/` remain ignored and uncommitted.
