# 비전: 반품/환불 모듈 — OrderFlow 플랫폼

> **브라운필드 프로젝트.** 이 문서는 기존 시스템에 대한 변경 사항을 기술합니다.
> Current State 섹션은 필수입니다. 요구사항 및 설계 생성 전에 AIDLC가
> 무엇이 이미 존재하는지 이해할 수 있는 컨텍스트를 제공합니다.

---

## Current State (현재 상태)

OrderFlow는 TypeScript 기반 Node.js로 구축된 기존 e-커머스 주문 관리 플랫폼입니다.
주문 생성, 결제 캡처, 풀필먼트 라우팅, 배송 알림을 처리합니다. 현재 반품(Return) 또는
환불(Refund) 기능은 없습니다. 반품을 원하는 고객은 이메일로 고객지원에 문의하며,
환불은 재무 팀이 결제 공급자의 대시보드에서 수동으로 처리합니다.

기존 플랫폼은 3개의 백엔드 서비스(order-service, payment-service, notification-service)와
React 프런트엔드로 구성됩니다. 모든 서비스는 AWS ECS Fargate에 배포되어 있으며,
주 데이터 저장소는 PostgreSQL입니다.

---

## 추가하려는 것

고객이 기존 스토어프런트에서 반품 요청을 셀프서비스로 처리하고, 운영 담당자는 플랫폼을
떠나지 않고도 환불을 검토·승인·처리할 수 있는 반품/환불 모듈입니다.

---

## 이번 이터레이션의 범위(IN) 기능

- 고객용 반품 요청 폼: 주문 선택, 품목 선택, 반품 사유 선택
- 고객용 반품 요청 상태 추적(제출됨, 승인됨, 거절됨, 환불됨)
- 운영 대시보드: 열린 반품 요청 보기, 메모와 함께 승인/거절
- 기존 payment-service 연동을 통한 환불 자동 처리
- 각 상태 변경 시 notification-service를 통한 고객 이메일 알림
- 반품 사유 코드: damaged, wrong item, changed mind, other

## 이번 이터레이션 범위에서 명시적으로 제외(OUT)

- 반품 배송 라벨 생성 (당분간 수동, Phase 2)
- 품목 단위 부분 환불 (MVP에서는 전체 주문 환불만)
- 재고/입출고 관리 연동 (Phase 2)
- 사기 탐지 또는 반품 남용 방지 (Phase 3)
- 셀프 서비스 교환(반품 + 재주문 통합 흐름, Phase 2)
- 반품 분석/리포트 대시보드 (Phase 2)

---

## 변경되어서는 안 되는 것

- 주문 생성, 결제 캡처, 풀필먼트 흐름 — 수정 금지
- 주문/결제/고객을 위한 기존 PostgreSQL 스키마 — 추가 변경만 허용
- notification-service의 API 컨트랙트 — 그대로 사용하며 수정 금지
- 기존 React 프런트엔드 컴포넌트 라이브러리 및 디자인 시스템

---

## 미해결 질문

- 반품 요청에 승인 단계를 둘지, 아니면 정책 규칙(예: 30일 이내, 최종 세일 품목 아님)에 따라 자동 승인할지?
- 운영 대시보드에서 반품 요청의 소유자가 누구인지 — 고객지원 팀, 창고 팀, 또는 둘 다 다른 뷰로?
- 환불을 승인 즉시 처리할지, 일 단위 배치로 처리할지?
- 시스템이 강제해야 하는 반품 기간 정책(예: 배송 후 30일)이 있는지, 아니면 당분간은 케이스 바이 케이스인지?
