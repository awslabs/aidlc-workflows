   acceptance — ancestor rules and lazily discovered distribution instructions
   contaminate the context.
2. **Minimal capture-only project.** Test-owned `.devin/hooks.v1.json` + a logger
   that records one parsed stdin event per uniquely named file, returns exit 0,
   writes no control JSON to stdout. Native hook JSON with no outer `hooks` wrapper.

   `SessionEnd`.** A blank matcher captures all tools. Do not add an undocumented

   read-only subagent tasks. Live approval choices in the fixture are test UI
   choices, not authorization for project changes.

   `tests/fixtures/devin-hook-payloads/captured-3000.6.14.json` +
   `capture-provenance.json`. Replace only fixture paths/identifiers with
   placeholders; preserve property names, nesting, booleans, missing-vs-null,
   response status, correlation relationships. No secrets, no real document
   content, no arbitrary user prompts.
6. **STOP gate before S06–S09.** Write a short contract table from captures:
   native field → core equivalent → output reverse mapping → identity source →
   unsupported cases. If question output, reviewer identity, or terminal
   completion cannot be established, STOP that dependent step.

unavailable, mark the relevant capture rows BLOCKED and continue only independent
steps. A failure caused by missing credentials/trust/permissions/version/platform
is BLOCKED, not PASS.

## Test cycle (runbook §S01.5)

For every behavioral step:
1. Add the smallest regression test against current behavior.
2. Run that test and save the expected failure. A syntax/import/environment
   failure is not a valid red test.
3. Implement the authored-source change.
4. Run `bun scripts/package.ts`.
5. Rerun the target test; then its related suites.
6. Inspect `git diff --stat`, `git diff --check`, and the authored diffs.

Run full regeneration after shared-source edits. t331 compares Devin core
TypeScript against Claude core TypeScript; regenerating only Devin after a core
edit creates artificial parity failures.
