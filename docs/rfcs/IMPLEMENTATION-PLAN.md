## Decisions locked (from review)

- **Q1**: contract-design is a NEW stage right after units-generation;
  delivery-planning stays the inception capstone. Contracts are NOT folded into
  delivery-planning (different concern: contracts = inter-unit API/event/schema
  specs by the architect; delivery-planning = Bolt sequencing/team allocation by
  the delivery agent).
- **Q2**: full renumbering is fine. **Impact beyond numbers**: stage numbers
  appear in prose (knowledge files, stage NOTEs, the stage-protocol Bolt
  glossary "stages 3.1–3.7"). Those prose references must be updated too — tracked
  as explicit steps.
- **Q3**: first commit = branch create + RFC (html only; md deleted).
- **Q4**: each task runs the FULL build (`bun scripts/package.ts`) + `--check`
  across all four harnesses (claude, kiro, kiro-ide, codex).
- **Q5**: `blueprint-shape` sensor — full implementation.
- **Q6**: **Option C** (decided after discussion) — stable `cmp-NNN`/`ent-NNN`/
  `rule-NNN` IDs produced by the owning stage; downstream stages REFERENCE those
  IDs (no file re-emission, no literal carry-forward). The `blueprint-shape`
  sensor validates shape + cross-stage ID references. Stage bodies get light
  prose updates to emit IDs and reference upstream IDs — NOT full carry-forward
  rewrites.
- **Q7**: push per task.
