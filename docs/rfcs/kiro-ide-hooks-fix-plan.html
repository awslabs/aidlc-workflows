Kiro IDE Hooks Fix — Implementation Plan

Branch: fix/kiro-hooks (off v2) · Status: awaiting approval · Scope: Kiro IDE harness only (harness/kiro-ide/) + one shared core helper + tests/docs.

1. Problem (empirically verified)

Captured live inside Kiro IDE 0.12-main by registering probe .kiro.hook files. Kiro IDE delivers hook context through an environment variable USER_PROMPT, not stdin. The IDE opens stdin but never writes/closes it, so the current adapter's Bun.stdin.text() always hits its 2s timeout and proceeds with an empty payload — every payload-dependent hook silently no-ops.

USER_PROMPT carries JSON shaped like:

{ "toolName": "fs_write", "toolArgs": {}, "toolResult": "Created the /abs/path/file.md file.", "toolSuccess": true }

Critical limitation: toolArgs is always empty {}. The IDE never passes tool inputs. So the file path is only recoverable from the toolResult prose, and the shell command is unrecoverable (its toolResult is only stdout + exit code).

Out of scope (CLI): the Kiro CLI uses a different mechanism (agent-JSON hooks block + live stdin with populated tool_input) and works today. The CLI adapter (harness/kiro/hooks/aidlc-kiro-adapter.ts) is not touched. A separate, known CLI issue (conductor self-approves gates in one turn) is NOT a hook-payload bug and is tracked separately.

2. Design principle: separate adapters, no runtime branching

The two adapters are already separate authored files, each shipped into its own dist by its manifest:

  • harness/kiro/hooks/aidlc-kiro-adapter.ts — CLI (stdin + tool_input)
  • harness/kiro-ide/hooks/aidlc-kiro-adapter.ts — IDE (this fix)

The build substitutes the right adapter per dist. No if (CLI) … else (IDE) forks at runtime. The fix lives entirely in the IDE adapter's input layer; the byte-shared core hook bodies (aidlc-audit-logger.ts, etc.) and their Claude-shaped {tool_input:{file_path}} contract are unchanged.

3. The four issues and their fixes

#IssueFixHooks affected
1 stdin is dead; context arrives via USER_PROMPT env var IDE adapter reads process.env.USER_PROMPT instead of stdin. Drop the 2s timeout entirely. all payload-dependent
2 toolArgs always empty → no file path / command File path: scrape from toolResult prose (Option A, strict, fail-open). Command: unrecoverable → see #3. audit-logger, sensor-fire
3 runtime-compile's command filter needs the command string Drop the command filter on the IDE; dispatch the core compile, which already self-gates on the audit tail (idempotent + cheap). runtime-compile
4 sync-statusline needs the task slug from the payload Payload-independent: read the latest STAGE_STARTED slug from the audit tail; update state only if it differs from Current Stage. sync-statusline

Option A — toolResult path-extraction (confirmed wordings)

toolNametoolResultcanonicalregex
fs_writeCreated the <PATH> file.Write/^Created the (.+) file\.$/
str_replaceReplaced text in <PATH>Edit/^Replaced text in (.+)$/
fs_appendAppended the text to the <PATH> file.Edit/^Appended the text to the (.+) file\.$/
Strict + fail-open: only these three wordings match. No match → exit 0 (advisory miss, no audit/sensor row for that write). No mtime fallback for now — the framework writes several files under the record root every cycle (audit shard, health heartbeats, runtime-graph), so "newest mtime" would frequently point at one of those, not the artifact. The prose names the exact user-written file with no race. Both hooks are advisory; a missed row never corrupts workflow state (the state machine drives off transition events, not artifact-write rows).

5. Work items

5.1 IDE adapter input layer (issues 1 + 2)

  • Replace the stdin-read block with a USER_PROMPT env parse. Remove the Promise.race / 2s timeout.
  • Add extractWrittenPath(toolName, toolResult) implementing the three strict patterns; map fs_write→Write, str_replace/fs_append→Edit.
  • audit-and-sensors target: build {tool_input:{file_path}} from the scraped path; fail-open (return null) when no path.

5.2 runtime-compile IDE target (issue 3)

  • Drop the tool !== "Bash" / command checks for the IDE; always forward to the core aidlc-runtime-compile.ts, which gates on the audit tail.

5.3 sync-statusline payload-independent (issue 4)

  • New shared core helper in aidlc-lib.ts (or reuse findAllEvents(audit, "STAGE_STARTED")): return the latest STAGE_STARTED slug.
  • IDE state-sync target: read that slug, compare to Current Stage in state, call set-status --stage <slug> only on difference. No payload read.

5.4 Tests (no live IDE needed)

  • Unit: drive the IDE adapter with USER_PROMPT env fixtures — assert path extraction for create/edit/append, fail-open on unknown wording.
  • Unit: state-sync and runtime-compile fire off an audit fixture with no payload.
  • Guard: the two adapters remain distinct (CLI uses stdin, IDE uses env).

5.5 Docs + release

  • Update docs/guide/harnesses/kiro-ide.md "How hooks work" → env-var mechanism.
  • bun scripts/package.ts + --check; bump aidlc-version.ts + README badge + CHANGELOG entry.
