requirements-analysis-questions.mdProduct Agent · 4 questions

Before I write the requirements

Four decisions shape everything downstream. Each recommendation is also present in the file and answerable from the terminal.

1 · What platform should the to-do app run on?

2 · Where should tasks be stored?

3 · Who uses it?

4 · Which features are in the first version?

Terminal-complete: answers save to answers-NNN.json and fold back into the same questions file.

1 · Platform

Why now

This is the first fork in the road: a browser app needs no install and no backend, a CLI needs neither UI nor storage design, a mobile app needs a store pipeline. Every later stage — code generation, build and test, deployment — reads this answer.

Trade-offs
OptionYou getYou give upCost / risk
Web appRuns anywhere, fastest to a usable buildOffline is only as good as the browserLow
CLITiny surface, trivial testingNo visual list, awkward for most peopleLow
DesktopNative feelPackaging per OSMedium
MobileAlways at handStore review, two platformsHigh
Recommendation: Web app. For a lightweight express build it is the shortest path to something you can click on, and it keeps storage (Q2) and users (Q3) simple.
